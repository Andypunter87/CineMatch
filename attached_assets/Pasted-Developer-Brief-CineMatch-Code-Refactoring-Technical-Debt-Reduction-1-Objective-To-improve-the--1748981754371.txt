Developer Brief: CineMatch Code Refactoring & Technical Debt Reduction
1. Objective

To improve the overall quality, maintainability, and scalability of the CineMatch codebase. This project will focus on reducing technical debt, improving developer experience, and ensuring the long-term health of the application by addressing key issues identified in a recent code review.

2. Background

A comprehensive code review revealed that while the application is built on a solid, modern tech stack, it is accumulating technical debt. Key problem areas include inconsistent code style, a lack of documentation, overly complex components, insufficient error handling, and outdated dependencies. This brief outlines the specific tasks required to rectify these issues.

3. Scope of Work & Implementation Guidelines

The developer will execute the following tasks. All work should be done in a new feature branch.

Task 1: Enforce a Consistent Code Style

Action: Integrate and configure Prettier and ESLint to enforce a single, consistent code style. The configuration should be added to the project's root.
Action: Add lint and format scripts to the scripts section of package.json.
Action: Run the formatter on the entire existing codebase (/client and /server directories) to establish a clean baseline.
Task 2: Refactor Overly Complex Components

Target Files: client/src/components/FilmCard.tsx and client/src/components/Recommendations.tsx.
Action: Decompose FilmCard.tsx.
Isolate the user interaction buttons ("Yes", "No", "Add to Watchlist") into a new, separate component.
Separate the data presentation logic from the action handling logic.
Action: Refactor Recommendations.tsx.
The logic for fetching, processing, and managing recommendation data (currently within the component and the use-recommendation-engine.tsx hook) should be clearly separated from the rendering/UI logic.
Create smaller sub-components for rendering individual parts of the recommendations page if necessary.
Task 3: Implement a Global Error Handling Strategy

Action: Utilize the existing ErrorBoundary component (client/src/components/ui/error-boundary.tsx) by wrapping it around the main application router in client/src/App.tsx. This will catch and gracefully handle rendering errors.
Action: For asynchronous operations (e.g., API calls in hooks like use-film-feedback.tsx), implement consistent try/catch blocks.
Action: On error, use the existing toaster component (client/src/components/ui/toaster.tsx and use-toast.ts hook) to provide clear, user-friendly feedback. Avoid console.log for user-facing errors.
Task 4: Update Project Dependencies

File: package.json
Action: Run npm outdated to identify all outdated packages.
Action: Update all dependencies to their latest stable and secure versions. Pay special attention to major packages like React, Firebase, and Vite.
Action: After updating, run the full test suite using the run-tests.sh script to ensure that the updates have not introduced breaking changes. Resolve any issues that arise.
Task 5: Improve Code Documentation

Action: Add JSDoc/TSDoc comments to all custom hooks in the client/src/hooks directory. The documentation should explain the purpose of the hook, its parameters, and what it returns.
Action: Add high-level documentation to the refactored components from Task 2, explaining their responsibilities and props.
Action: Create or update a CONTRIBUTING.md file in the root of the project, briefly explaining the new code style conventions, how to run the linter, and the testing strategy.
4. Key Deliverables

A single Pull Request containing all the code changes from the tasks outlined above.
An updated package.json and package-lock.json with the latest dependencies.
A new or updated CONTRIBUTING.md file.
5. Success Criteria

The ESLint and Prettier checks pass on the entire codebase.
The FilmCard and Recommendations components are successfully broken down into smaller, more manageable components.
The application gracefully handles common errors without crashing and provides useful feedback to the user.
All project dependencies are updated, and the test suite passes without errors.
The codebase is more readable and easier to navigate due to improved documentation and consistent styling.
